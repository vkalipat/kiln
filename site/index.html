THE KILN HANDBOOK

Good ideas.
Finished work.

A terminal harness for the work between a question and a working result.

Kiln gives frontier models tools, persistent context, and scoped collaborators. Use it to research a problem, compare ideas, or build something you can actually inspect.

  • One conversation that can keep going.
  • Parallel work with clear ownership.
  • Results backed by artifacts and checks.

GETTING STARTED

From install to first session.

You’ll need Git and Bun 1.3.14 or newer. Install from the source repository:

Terminal
git clone https://github.com/vkalipat/kiln.git
cd kiln
bun install --frozen-lockfile
bun link

Connect a provider. Check your setup.

Terminal
kiln auth login
kiln doctor --json
  • Choose subscription sign-in or API-key access in the login flow.
  • doctor checks local configuration. It does not test live authentication, quota, or service health.
  • Open a terminal in your own project, then run kiln. Opening the interface does not call a model; submitting a task can use paid access.
↳

Already installed? In the Kiln checkout, run git pull --ff-only, then bun install --frozen-lockfile and bun link. Restart Kiln after updating.

THE EVERYDAY WORKFLOW

Give it an outcome.
Keep the same conversation.

Start with what should exist when the work is done. Give Kiln enough context to make decisions without prescribing every step.

  • Name the deliverable. A working feature, research report, ranked shortlist, or tested prototype.
  • Define the scope. The project, source material, constraints, and decisions you want to retain.
  • Make “done” observable. Describe the behavior, evidence, or checks that would satisfy the request.
  • Steer as you go. A message during work updates the task. A follow-up continues the same session.
EXAMPLE TASK

Build a CSV importer in this project. Handle missing headers and malformed rows. Keep the existing UI style. Finish when the relevant tests pass and the import flow works in the rendered app. Report any remaining gaps.

Open the workspace, or use the command line.

Terminal
kiln task "Implement the importer and verify malformed input handling" --cwd .

For independent features, ask for parallel work with separate file scopes and acceptance checks. The parent operator reviews the handoffs and integrates the result.

Research & ideation

Ask for sources, competing approaches, assumptions, and a test that could change the decision. Substantial idea search can use Kiln’s dedicated ideation workflow.

Implementation

Describe the behavior and constraints. Let the operator choose the steps, use tools, inspect results, and repair failures within that scope.

Need explicit phase checkpoints? See the advanced workflow commands. The persistent operator is the simplest starting point.

FRONTIER MODELS

Good judgment needs room.

Kiln keeps instructions focused and lets the selected model reason about the task. Routing matches jobs to compatible models; reasoning effort is a separate choice.

  • Inspect the configured roles before changing them.
  • Use more reasoning effort when the task warrants it. xhigh appears as ultra in the TUI.
  • Keep verified context across follow-ups. Recheck when the inputs, artifacts, or evidence change.
  • A ranking is dated evidence, not a guarantee that a model is best for every task.
Inspect your configuration
kiln model roles --json
kiln mode show

To choose an effort explicitly, use kiln mode set xhigh. Use kiln mode set auto to restore role defaults.

INTEGRATIONS

Specialized tools.
One operator.

Jev Optional · experimental workflows

Jev handles constrained decisions: ambiguous routing handoffs, browser actions, and research passage classification. The frontier model remains responsible for the plan and the final assessment.

Enable for new sessions
kiln auth key jev
kiln integrations jev enable
kiln doctor --require jev --json
  • Enter the key in the masked prompt. Don’t put credentials into task prompts.
  • Browser workflows operate on an existing, owned native tab with explicit actions and outcome checks.
  • Research workflows capture bounded sources, citations, contradictions, and unknowns.
  • New settings apply to new sessions. A classifier label or passed browser check is not proof of the entire task.

Hindsight Optional · bring your own server

Use project memory when you need curated knowledge across runs. Hindsight requires a running server and an explicit project bank; Kiln does not provision them or automatically retain conversations.

Inspect a local memory configuration
kiln memory status --url http://127.0.0.1:8888 --bank example-project

This status command is offline. Configure authentication with kiln auth key hindsight when your server requires it.

CONTINUITY

Pick up where you left off.

Keep the run ID from the output. Resume that run to retain its context, artifacts, model selections, and recorded usage.

Continue an existing task
kiln task resume RUN_ID "Continue the remaining checks"

# Or reopen it in the terminal interface
kiln --run RUN_ID
  • Press Esc in the TUI to request a pause. Ctrl + C interrupts a CLI task.
  • kiln task resume RUN_ID without a message only reports retained state.
  • Uncapped sessions keep usage accounting and loop monitoring. Provider, tool, and concurrency limits still apply.
  • Existing runs retain their saved allocations. A new default does not change a resumed run.
Limits and inspection
# Inspect defaults and a run's latest monitor snapshot
kiln task limits
kiln task monitor RUN_ID --json

To remove aggregate dollar and active-time limits for future native sessions, explicitly run kiln task limits --uncapped.

The monitor flags repetition and context growth; it does not judge task quality. Finite dollar allocations are not absolute invoice ceilings.

BEFORE YOU START

Ready is something you check.

The core harness is available in v0.1.1. The release passed 2,307 automated tests, typechecking, and evaluation integrity checks. Verify the configuration on your own machine:

Local readiness
kiln doctor --json
Persistent operator & scoped teamsAvailable
Jev browser & research workflowsExperimental · requires key
Hindsight project memoryRequires server & bank
Live provider access & quotaAccount dependent
Scientific or challenge performanceNot established by software tests
  • A ready: true result is an offline configuration check, not a live service guarantee.
  • Review the delivered artifacts, recorded checks, and unresolved gaps. A finished turn alone is not verified completion.
  • Shell and file tools act in your local environment. Specify scope and authorize external actions deliberately.

Preparing the harness does not start a challenge or submit anything. Challenge prompts, datasets, compute, and acceptance criteria belong to the actual run.
